# Clinical TabReD: полное руководство для докладчика

Этот документ для того, кто будет выступать с презентацией, но не занимается машинным обучением.
Здесь простыми словами объяснено:
- что мы делали и зачем;
- как устроены данные и модели;
- что означает каждая метрика и как её читать;
- что получилось.

В конце собраны вероятные вопросы слушателей с ответами и словарь терминов.

Все числа взяты из сохранённых результатов эксперимента (`docs/RESULTS.md`, папка `tables/`,
`key_numbers.json`). Рисунки лежат в `figures/` и `diagrams/` этой папки.

## 1. О чём проект, в одном абзаце

Медицинские модели обучают на данных пациентов **из прошлого**, а применяют к пациентам **в
будущем**. За это время многое меняется: население, правила диагностики, анкеты, лабораторное
оборудование. Обычно качество модели проверяют на *случайно* отложенной части данных, и тогда такие
изменения не видны. Работа **TabReD** (Rubachev и др., 2024) показала на 8 промышленных наборах
данных, что такая случайная проверка вводит в заблуждение. Медицинских данных в TabReD не было.

**Наша цель:** построить «клинический TabReD», то есть набор медицинских данных с осью времени,
проверить на нём выводы TabReD и для каждого изменения во времени найти его **клиническую
причину**.

## 2. Базовые понятия (минимум, без которого дальше трудно)

- **Табличные данные.** Обычная таблица, как в Excel: одна строка — один человек (или одни роды),
  столбцы — его характеристики (возраст, вес, давление, ответы на вопросы анкеты).
- **Признак (feature).** Один столбец таблицы, то есть одна характеристика человека.
- **Целевая переменная (target, label).** То, что модель должна предсказать. У нас это всегда
  «да/нет»: есть ли у человека диагностированный диабет; родился ли ребёнок недоношенным.
  Это задача **бинарной классификации**.
- **Положительный класс.** Ответ «да» (диабет есть / роды преждевременные). Таких случаев мало:
  10–16% строк. Это называется **несбалансированные классы**, и это важно для метрик (раздел 6).
- **Модель.** Программа, которая по признакам человека выдаёт **вероятность** положительного ответа
  (например, «вероятность диабета 0,73»).
- **Обучение.** Модель смотрит на много примеров с известным ответом и подбирает внутренние
  параметры так, чтобы её вероятности совпадали с ответами.
- **Порог.** Чтобы превратить вероятность в ответ «да/нет», выбирают порог: если вероятность выше
  порога, ответ «да». От порога зависит баланс между пропущенными случаями и ложными тревогами.
- **Обучающая / валидационная / тестовая выборки.** Данные делят на три части:
  - **train**: на ней модель учится;
  - **validation**: на ней выбирают лучшие настройки модели и порог (это «репетиция экзамена»);
  - **test**: на ней модель проверяют **один раз** в самом конце (это «экзамен», которого модель
    раньше не видела).
- **Дрейф (distribution shift).** Данные меняются со временем, и модель, обученная на прошлом,
  работает на будущем хуже.

## 3. Данные: три источника

| | NHANES | BRFSS | Natality (рождаемость) |
|---|---|---|---|
| Что это | национальное обследование здоровья США (CDC): интервью + медосмотр + анализы крови | телефонный опрос о здоровье взрослых (CDC) | данные свидетельств о рождении всех детей в США (NCHS) |
| Одна строка | взрослый от 20 лет | взрослый респондент | одни роды у матери, проживающей в США |
| Что предсказываем | диагностированный диабет | диагностированный диабет | преждевременные роды (< 37 недель) |
| Периоды | 7 двухлетних циклов, 2005–2018 | 7 лет, 2017–2023 | 9 лет, 2016–2024 |
| Строк | 37 287 | 350 000 (по 50 000 в год) | 450 000 (по 50 000 в год из ~3,6 млн) |
| Признаков | 280 | 93 | 73 |
| Доля «да» | 13,3% (растёт: 10,4% → 16,4%) | 13,6% (ровно, провал в 2020) | 10,2% (9,6% → 10,5%) |

**Почему именно эти данные.** Все три открытые (публичные), у всех есть ось времени, и все из
разных областей медицины: обследование с анализами, телефонный опрос, документы о рождении.
**Почему выборка по 50 000 в год.** Полные данные огромные (миллионы строк). Случайной выборки
достаточно для выводов, и так же поступали авторы TabReD. Выборка фиксирована (seed 42), поэтому её
можно воспроизвести.

## 4. Пайплайн шаг за шагом

Схема: `diagrams/d01_methodology.png`. Семь шагов.

### Шаг 1. Загрузка данных
Скачиваются официальные файлы CDC/NCHS. Файлы natality очень большие (~5 ГБ каждый в распакованном
виде), поэтому их не распаковывают, а читают «потоком» и сразу делают случайную выборку.

### Шаг 2. Построение таблиц (очистка)
- Коды «не знаю», «отказ от ответа», «не спрашивали» превращаются в **пропуски** (пустые значения).
  Иначе модель приняла бы код «99 = не знаю» за число 99.
- В BRFSS одни и те же вопросы в разные годы назывались по-разному, и их **объединили**.
- Оставлены только признаки, которые есть **во всех периодах**. Если вопрос задавали только в
  некоторые годы, модель могла бы по нему «узнать год», а не изучить болезнь.
- Удалены технические столбцы: номера анкет, веса опроса, даты, почти пустые столбцы (> 95% пропусков).
- Строки с пропусками **не удаляются**: пропуски потом заполняются автоматически (шаг 5).

### Шаг 3. Защита от «утечки» (leakage)
**Утечка** — это когда среди признаков есть подсказка, прямо выдающая ответ. Пример: вопрос
«Принимаете ли вы инсулин?» почти равносилен ответу «есть диабет». С такой подсказкой модель
показала бы блестящий результат, но бесполезный: в реальности эту информацию не получить до
диагноза. Что сделано:
- удалены все вопросы, где упоминается диабет, инсулин, сахар, глюкоза, гемоглобин A1C. Их задают
  только диабетикам, так что даже сам факт пропуска выдаёт ответ;
- удалены **следствия диагноза** (например, прививка от пневмококка, которую рекомендуют
  диабетикам);
- в данных о родах удалено всё, что известно только **во время или после родов** (вес ребёнка,
  оценка по Апгар, реанимация, способ родоразрешения). Оставлено лишь то, что известно до родов;
- **численная проверка**: для каждого признака посчитано, насколько хорошо он *в одиночку*
  предсказывает ответ. Ни один не превысил порог подозрительности (ROC-AUC 0,80; что это такое,
  см. раздел 6). Самые сильные признаки разумные: возраст, ИМТ, самооценка здоровья, многоплодная
  беременность.

### Шаг 4. Разбиение на выборки (как в TabReD)
Схема: `diagrams/d03_splits.png`. Это ключевая идея всей работы.

- **Основное временное разбиение (default):** учимся на ранних годах, настраиваемся на следующем
  году, проверяем на самых поздних годах. Например, для BRFSS: учёба 2017–2020, настройка 2021,
  экзамен 2022–2023. Это честная имитация реального применения модели.
- **Скользящие окна (sliding window, 3 штуки):** учимся на 3 периодах подряд, настраиваемся на
  следующем, проверяем на следующем за ним. Окно сдвигается, и получаются 3 независимые проверки
  в разные годы.
- **Случайные разбиения (random, 3 штуки):** берутся *те же самые строки*, что в окне, но
  перемешиваются и делятся случайно на части *того же размера*. Это «обычная» проверка, которую
  делают в большинстве работ.

**Зачем так.** Случайное и временное разбиения отличаются только одним: учитывается ли порядок
времени. Поэтому разница в результатах между ними показывает, насколько обычная проверка
переоценивает (или недооценивает) модель в реальном будущем.

### Шаг 5. Обучение моделей
Схема: `diagrams/d02_architecture.png`.
1. **Предобработка** (одинаковая для всех моделей):
   - пропуски в числах заменяются медианой, в категориях — самым частым значением;
   - числа приводятся к одному масштабу;
   - категории (например, «раса: 1, 2, 3…») превращаются в отдельные столбцы «да/нет»
     (one-hot), потому что код категории — это не количество.

   Предобработка «учится» **только на обучающей выборке**, чтобы не подсмотреть данные экзамена.
2. **Подбор настроек (гиперпараметров):** у каждой модели есть настройки, например глубина деревьев.
   Мы пробуем несколько вариантов из небольшой сетки, и для каждого вычисляется качество на
   валидационной выборке. Остаётся лучший вариант (по метрике PR-AUC, см. раздел 6).
3. **Выбор порога:** на валидации выбирается порог, при котором F1 максимален.
4. **Экзамен:** модель с выбранными настройками и порогом **один раз** проверяется на тесте.

**Несбалансированность классов** учтена: модели дают положительным примерам больший вес, иначе они
научились бы всегда отвечать «нет».

Всего обучено 5 моделей × 7 разбиений × 3 набора данных = **105** конфигураций с подбором.

### Шаг 6. Оценка
- Метрики качества на тесте (раздел 6).
- **Доверительные интервалы (bootstrap):** тестовые строки 1000 раз случайно перевыбираются с
  возвращением, и метрика пересчитывается. Средние 95% значений дают интервал. Если интервалы двух
  моделей сильно перекрываются, разница может быть случайной.
- **Парный bootstrap:** две модели сравниваются на *одних и тех же* перевыборках. Это точнее
  показывает, значима ли разница. «Значимо» означает, что 95%-интервал разницы не содержит ноль.
- **Кросс-валидация (5-fold):** данные периода обучения делятся на 5 частей; модель 5 раз учится
  на 4 частях и проверяется на пятой. Получается качество *внутри того же времени* и его
  стабильность.
- **Новый анализ, сравнение на одном и том же периоде:** объяснён в разделе 7.3.

### Шаг 7. Анализ дрейфа и его причин
- **Доменный классификатор:** простая модель пытается отличить строки старых лет от строк нового
  года. Если отличает легко, данные сильно изменились (подробнее в разделе 6.8).
- **PSI / TVD:** насколько изменилось распределение каждого признака между первым и последним
  периодом.
- **События с клинической причиной:** изменения из официальной документации (замена лабораторного
  анализатора, реформа страхования, переформулировка вопроса анкеты, закон штата), измеренные в
  каждом периоде.

## 5. Модели: как они работают (кратко)

Использовано пять моделей. Первые две — классические, вторые две — так называемые **GBDT**
(градиентный бустинг деревьев решений), пятая — нейронная сеть.

### 5.1 Логистическая регрессия (Logistic Regression)
- **Идея:** каждому признаку даётся «вес» (насколько он повышает или понижает риск); веса
  складываются, и сумма превращается в вероятность от 0 до 1 (функция-сигмоида).
- **Аналогия:** балльная шкала риска, как у врача: +2 балла за возраст, +3 за лишний вес и т. д.
- **Плюсы:** простая, быстрая, понятная. **Минусы:** не видит сложных сочетаний признаков
  (например, «риск высок только если одновременно А и Б»).
- Это базовая модель для сравнения.

### 5.2 Случайный лес (Random Forest)
- **Дерево решений:** цепочка вопросов «да/нет»: «ИМТ > 30? → возраст > 50? → …», в конце ответ.
- **Лес:** 300 деревьев, каждое обучено на случайной части данных и признаков; итог — среднее
  мнение всех деревьев («голосование»).
- **Плюсы:** ловит сложные сочетания, устойчив к шуму. **Минусы:** деревья строятся независимо,
  поэтому лес обычно уступает бустингу.

### 5.3 XGBoost и 5.4 LightGBM (градиентный бустинг, GBDT)
- **Идея:** деревья строятся **по очереди**, и каждое следующее исправляет ошибки предыдущих.
  Сначала грубый прогноз, потом поправка, потом поправка к поправке, и так 300 раз.
- **Аналогия:** команда, где каждый новый участник занимается именно теми случаями, на которых
  ошиблись предыдущие.
- XGBoost и LightGBM — две популярные реализации одной идеи. LightGBM строит деревья немного иначе
  и обычно быстрее.
- **Плюсы:** как правило, **лучшие модели для табличных данных**; это известный результат
  литературы, и TabReD тоже это подтверждает.

### 5.5 Нейронная сеть (MLP, многослойный перцептрон)
- **Идея:** слои «нейронов»; каждый нейрон берёт взвешенную сумму входов и пропускает её через
  нелинейную функцию. 1–2 скрытых слоя (64 и 32 нейрона).
- **Обучение по эпохам:** одна эпоха — один проход по всем обучающим данным. После каждой эпохи
  смотрим ошибку на валидации; если она 10 эпох подряд не улучшается, останавливаемся (**ранняя
  остановка**) и берём лучшую эпоху. Это защищает от **переобучения**, то есть от «зубрёжки»
  обучающих примеров вместо общих закономерностей.
- Кривые обучения показаны на `figures/fig06_mlp_training_curves.png`.
- **Важно:** у нас простая нейросеть из scikit-learn, а не самые сильные нейросети из TabReD
  (MLP-PLR, FT-Transformer). Это ограничение работы.

## 6. Метрики: что означают и как их читать

Это самая важная часть для ответов на вопросы.

### 6.1 Матрица ошибок (confusion matrix)
Все ответы модели при выбранном пороге раскладываются на 4 группы:

| | Модель сказала «нет» | Модель сказала «да» |
|---|---|---|
| **На самом деле «нет»** | TN — верно отрицательный | FP — ложная тревога |
| **На самом деле «да»** | FN — пропущенный случай | TP — верно найденный |

**Реальный пример (NHANES, тест 2015–2018, модель MLP, порог 0,72), 10 444 человека:**

| | сказала «нет» | сказала «да» |
|---|---|---|
| нет диабета | 7 914 (TN) | 886 (FP) |
| есть диабет | 541 (FN) | 1 103 (TP) |

Рисунок: `figures/fig05_confusion_matrices.png`.

### 6.2 Accuracy (точность / доля верных ответов)
`(TP + TN) / все`. В примере: (7 914 + 1 103) / 10 444 = **86,3%**.
**Почему её нельзя использовать как главную метрику:** при редком положительном классе она
обманчива. Модель, которая *всегда* отвечает «нет диабета», получила бы 84,3% (диабет у 15,7%), не
найдя ни одного больного. В данных о родах ещё нагляднее: «всегда нет» даёт 89,6%, а наша модель
85,7%, хотя наша модель полезна, а «всегда нет» — нет. Поэтому accuracy мы показываем, но не
опираемся на неё.

### 6.3 Precision (точность положительных ответов)
`TP / (TP + FP)`: из тех, кого модель назвала больными, какая доля действительно больна.
В примере: 1 103 / 1 989 = **0,55**. Каждая вторая «тревога» настоящая.

### 6.4 Recall (полнота, чувствительность)
`TP / (TP + FN)`: какую долю реально больных модель нашла.
В примере: 1 103 / 1 644 = **0,67**. Найдено две трети больных, треть пропущена.
В медицине recall часто важнее: пропущенный больной обычно «дороже» ложной тревоги.

### 6.5 F1-мера
Среднее гармоническое precision и recall: `2·P·R / (P + R)`. Высокое, только если **обе** метрики
высокие. В примере **0,61**. По F1 мы выбираем порог на валидации.

### 6.6 Порог: компромисс
Понижаем порог → модель чаще говорит «да» → recall растёт, precision падает (больше ложных тревог).
Повышаем → наоборот. Порог выбирается на валидации (максимум F1), а не на тесте. Иначе мы
«подогнали бы ответ под экзамен», и результат был бы завышен.

### 6.7 ROC-AUC (главная метрика)
- **Простое определение:** вероятность того, что модель поставит **случайно выбранному больному
  более высокий риск, чем случайно выбранному здоровому**.
- **Шкала:** 0,5 — угадывание (подбрасывание монеты); 1,0 — идеальное разделение.
  Ориентиры: 0,7–0,8 — приемлемо, 0,8–0,9 — хорошо, > 0,9 — отлично.
- **Почему она главная:** не зависит от порога и от доли больных, а доля больных у нас меняется
  со временем. Поэтому ROC-AUC разных лет можно честно сравнивать. TabReD тоже использует ROC-AUC
  для задач классификации.
- **ROC-кривая** (`figures/fig04_roc_curves.png`): по горизонтали доля ложных тревог, по вертикали
  доля найденных больных, при всех возможных порогах. Чем ближе кривая к левому верхнему углу, тем
  лучше. ROC-AUC — это площадь под этой кривой.
- **Наши значения:** NHANES ≈ 0,90 (отлично; есть анализы крови), BRFSS ≈ 0,83 (хорошо; только
  анкета), роды ≈ 0,75 (приемлемо; преждевременные роды трудно предсказать по данным до родов).
- **Маленькие разницы.** Разница 0,005 кажется крошечной, но на 100 000 тестовых строк она бывает
  статистически значимой. Для этого и нужны доверительные интервалы.

### 6.8 PR-AUC (площадь под кривой precision–recall)
- Показывает, насколько хорошо модель находит редкие положительные случаи без лишних тревог.
- **Как читать:** сравнивать с **долей больных**, потому что у случайной модели PR-AUC ≈ доле
  больных. NHANES: 0,65 при доле 0,157 (в 4 раза лучше случайного); BRFSS: 0,42 при 0,137;
  роды: 0,37 при 0,104.
- По PR-AUC на валидации мы выбираем настройки моделей, потому что положительных случаев мало.

### 6.9 Доверительный интервал 95% и «значимость»
- Запись `0,900 [0,892; 0,908]` означает: оценка 0,900, а с 95% уверенностью истинное значение
  лежит между 0,892 и 0,908 (по bootstrap).
- **Значимая разница** — 95%-интервал разницы не включает ноль. Если включает, разница может
  быть случайностью, и мы её не утверждаем.

### 6.10 Метрики дрейфа
- **ROC-AUC доменного классификатора:** та же ROC-AUC, но модель отличает «старые годы» от
  «нового года». 0,5 — периоды неотличимы (дрейфа нет); ближе к 1 — данные сильно изменились.
  Для случайных разбиений должно получаться ≈ 0,5, и это проверка корректности.
- **PSI (индекс стабильности популяции)** для числовых признаков: < 0,1 — мало изменений,
  0,1–0,25 — умеренно, > 0,25 — сильно.
- **TVD (расстояние полной вариации)** для категорий: какая доля людей «переместилась» между
  категориями (0 — без изменений, 1 — полностью другое распределение).

### 6.11 Метрики сравнения разбиений
- **«Random минус time»:** ROC-AUC при случайном разбиении минус ROC-AUC при временном (для
  одного окна и модели). **Плюс** означает, что обычная случайная проверка обещает больше, чем
  модель реально покажет в будущем (переоценка). **Минус** — наоборот.
- **Относительное преимущество над MLP, %** (как таблица 4 в TabReD):
  `(ROC-AUC модели − ROC-AUC MLP) / ROC-AUC MLP × 100%`. Показывает, насколько GBDT лучше
  нейросети, отдельно для временных и случайных разбиений.

## 7. Результаты: что получилось и как это объяснять

### 7.1 Лучшие модели — градиентный бустинг (во всех трёх наборах)
Рисунок `figures/fig02_default_auc_ci.png`, таблица `tables/t03_default_test_metrics.md`.

| Набор | Лучшая модель (тест, ROC-AUC) | Разброс между моделями |
|---|---|---|
| NHANES | XGBoost 0,900 [0,892; 0,908] | 0,876–0,900 |
| BRFSS | LightGBM 0,826 [0,823; 0,829] | ≈ 0,005 |
| Роды | XGBoost 0,750 [0,745; 0,756] | ≈ 0,006 |

- Это совпадает с TabReD: бустинг сильнее всего на табличных данных.
- **Чем больше признаков, тем сильнее различаются модели:** в NHANES (280 признаков) разброс
  0,024, а в BRFSS и родах всего около 0,005.
- **Интересный момент:** в NHANES на валидации (2013–2014) лучшей казалась нейросеть, но на
  экзамене (2015–2018) она значимо хуже XGBoost. Модель, лучшая «вчера», не обязательно лучшая
  «завтра».
- **При выбранном пороге:** в NHANES найдено ~2/3 больных диабетом, в BRFSS ~58%, в родах ~42%
  преждевременных родов. Последнюю задачу решать заметно труднее.

### 7.2 Случайная проверка против временной (сравнение TabReD)
Рисунок `figures/fig03_random_minus_time.png`, таблица `tables/t06_random_vs_time.md`.
- **NHANES:** случайная проверка завышает качество (до +0,02 в окне с тестом 2015–2016, значимо
  у 4 из 5 моделей) и **меняет рейтинг моделей:** нейросеть при случайной проверке 2-я, при
  временной 4-я.
- **BRFSS:** небольшое, но устойчивое завышение у **всех** моделей (+0,006…+0,007); значимо в 9
  из 15 случаев (тестовые годы 2021 и 2022).
- **Роды:** наоборот, временная проверка выглядит *лучше* (−0,003…−0,006). Объяснение в 7.3.

### 7.3 Новый анализ: сравнение на одном и том же периоде
Рисунок `figures/fig10_random_minus_time_same_period.png`.
**Проблема метода TabReD:** при случайном разбиении тест содержит строки *всех* лет окна, а при
временном — только *последнего* года. Если последний год сам по себе «легче» или «труднее», это
искажает сравнение. Поэтому мы оценили модель со случайного разбиения **только на строках того же
года**, что и временный тест.
- **Роды:** разница исчезает (нигде не значима). Поздние годы просто **легче предсказывать**:
  внутри одного и того же случайного теста ROC-AUC растёт с 0,735 на родах 2016 года до 0,761 на
  родах 2020 года, видимо, потому что информативные факторы риска (например, гипертензия) стали
  чаще. Вывод: «временная проверка лучше» — артефакт, и **переоценки при случайной проверке для
  преждевременных родов нет**.
- **BRFSS:** на том же периоде случайная проверка выше во **всех 15** случаях (по отдельности не
  значимо, но направление одинаковое везде), то есть небольшое устойчивое завышение.
- **NHANES, 2017–2018:** модель со случайного разбиения на людях 2017–2018 даже значимо *хуже*
  (≈ −0,04). Вероятная причина (гипотеза): в 2017–2018 сменили биохимический анализатор, и при
  смешивании старых и новых значений лабораторные признаки становятся менее согласованными.
- **Методический вклад работы:** без такого сравнения вывод для данных о родах был бы неверным.

### 7.4 Таблица 4 TabReD: преимущество бустинга над нейросетью
Таблица `tables/t08_improvement_over_mlp.md`.
TabReD обнаружил, что при временной проверке отрыв XGBoost от нейросети **уменьшается**. У нас он
**не уменьшается**: в NHANES он растёт (+0,28% при случайной → +0,97% при временной), в BRFSS и
родах почти не меняется (+0,19% → +0,24%; +0,85% → +0,84%). То есть на медицинских данных
случайная проверка скорее *скрывает* преимущество бустинга. Оговорка: наша нейросеть проще, чем в
TabReD.

### 7.5 Что меняется со временем и почему (дрейф с причинами)
Рисунки `figures/fig01_prevalence.png`, `fig07_domain_shift.png`, `fig08_drift_events.png`.

**Насколько сильно меняются данные** (ROC-AUC доменного классификатора, временные разбиения):
NHANES 0,86–0,97 (очень сильно), BRFSS 0,76–0,79 (заметно), роды 0,55–0,59 (почти нет). Для
случайных разбиений везде ≈ 0,50, как и должно быть.

**Найденные причины (по официальной документации CDC/NCHS):**
- **NHANES, смена лабораторного оборудования:** в 2013–2014 заменили гематологический анализатор
  (показатель RDW: 12,84% → 13,55% по данным CDC); в 2017–2018 сменили биохимический анализатор и
  лабораторию (ЛДГ +14,9%, АСТ −18,0% по сравнительному исследованию CDC).
- **NHANES, политика здравоохранения:** после реформы страхования 2014 года (Affordable Care Act)
  доля незастрахованных упала с 25,6% до 15,2%, а доля застрахованных по Medicaid выросла с 8,1%
  до 17,6%.
- **NHANES, рост диабета:** 10,4% → 16,4%. Это **сдвиг целевой переменной**.
- **BRFSS, изменения анкеты:** в 2021 переформулировали вопрос о личном враче (ответ «больше
  одного» 6,7% → 28,4%) и заменили вопрос о страховке; в 2022 из вопроса о расе убрали категорию
  «другая раса». Кроме того, опрос перешёл с домашних на мобильные телефоны.
- **Роды:** с 2017 Калифорния перестала сообщать семейное положение (закон штата; 0% → 12%
  пропусков); гипертензия беременных почти удвоилась (5,9% → 10,3%); курение до беременности
  сократилось втрое; в 2020 из-за COVID-правил в больницах стало больше пропусков в данных об отце.

### 7.6 Объясняет ли дрейф падение качества?
Таблица `tables/t12_drift_vs_performance.md`.
- **Сильнее дрейф — не значит хуже качество.** Самый сильный сдвиг данных (NHANES 2017–2018,
  смена анализатора, доменный ROC-AUC 0,97) **не дал** значимого разрыва. А значимый разрыв в
  NHANES (2015–2016) совпал со **сдвигом доли больных** (12,6% → 15,1%) и реформой страхования.
- **В BRFSS разрывы совпадают с годами изменения анкеты** (2021, 2022) и исчезают в 2023, где
  изменений анкеты не найдено.
- **Главный вывод:** важен **тип** изменения (сдвиг целевой переменной, переформулировка вопросов),
  а не его **размер**.

### 7.7 Кросс-валидация
Таблица `tables/t09_cross_validation.md`, рисунок `figures/fig09_cross_validation.png`.
Внутри периода обучения модели очень стабильны (разброс между 5 частями ≤ 0,005). Качество
«внутри своего времени» выше, чем на будущем, для NHANES (≈ 0,91 против 0,88–0,90) и BRFSS
(≈ 0,83 против 0,82–0,83), а для родов одинаковое (≈ 0,75). Это та же картина, что и в сравнении
случайной и временной проверки.

### 7.8 Итог в одной таблице (ответ на исследовательский вопрос)

| Утверждение TabReD | NHANES | BRFSS | Роды |
|---|---|---|---|
| Случайная проверка переоценивает качество в будущем | да, в окне со сдвигом доли больных | да, слабо, но устойчиво, в годы смены анкеты | нет (видимый обратный эффект — артефакт) |
| Случайная проверка меняет рейтинг моделей | да (MLP 2-я → 4-я) | нет | частично (бустинг остаётся первым) |
| Бустинг — лучшие модели | да | да | да |
| Отрыв XGBoost от нейросети уменьшается при временной проверке | нет, растёт | нет | нет |

**Короткая версия для финального слайда:** бустинг остаётся лучшим на медицинских данных.
Случайная проверка переоценивает модели и путает их рейтинг там, где меняется доля больных или
вопросы анкеты, но не в данных о родах. Чтобы отделить эффект времени от того, что одни годы просто
легче других, случайную и временную проверку нужно сравнивать на одном и том же периоде.

## 9. Ограничения (говорить честно)

- Одна фиксированная случайность (seed) и небольшие сетки настроек (в TabReD 15 повторов и 100
  попыток подбора). Значимость мы проверяем доверительными интервалами.
- Нет CatBoost и самых сильных нейросетей TabReD (MLP-PLR, FT-Transformer).
- В BRFSS и родах признаков меньше, чем в наборах TabReD. Мы сознательно не «добивали» их
  искусственными признаками.
- Объяснения причин (анализатор в NHANES 2017–2018, факторы риска в родах) — **гипотезы**,
  согласующиеся с данными, а не доказанные причинно-следственные связи.
- Веса опроса не использовались; в NHANES и BRFSS каждый год опрашивают разных людей; диабет
  определяется по самоотчёту о диагнозе (недиагностированный диабет считается «нет»).
- Это учебный бенчмарк, а не готовая медицинская система.

## 10. Вероятные вопросы и ответы

**— Зачем три набора данных, а не один?**
Это бенчмарк: выводы проверяются на разных типах медицинских данных. И выводы действительно
различаются (роды ведут себя иначе, чем диабет).

**— Почему ROC-AUC, а не accuracy?**
Больных мало (10–16%). Модель «всегда нет» получила бы высокую accuracy, ничего не найдя. ROC-AUC
не зависит от порога и от доли больных, которая меняется по годам.

**— Разница 0,005 — это вообще важно?**
Абсолютно она мала, но при 100 000 тестовых строк значима (интервал разницы не включает ноль).
Главное не размер, а то, что она систематическая: например, в BRFSS завышение есть у всех
15 комбинаций модели и окна.

**— Почему вы уверены, что нет утечки?**
Подсказывающие признаки удалены по правилам (диабетические вопросы, следствия диагноза, всё
послеродовое). Затем каждый оставшийся признак проверен численно: ни один в одиночку не
предсказывает ответ с ROC-AUC выше 0,80.

**— Почему бустинг лучше нейросети?**
На табличных данных среднего размера это известный результат. Деревья хорошо работают с
разнородными признаками, пропусками и порогами («ИМТ > 30»). Наша нейросеть простая, и с более
сильными архитектурами разрыв мог бы быть меньше.

**— Что такое «сдвиг целевой переменной»?**
Меняется сама доля больных (например, диабет 10,4% → 16,4%). Модель, обученная при одной доле,
неправильно калибрована при другой.

**— Почему сильный дрейф (анализатор) не испортил модель?**
Модель опирается в основном на признаки, которые изменились мало (возраст, ИМТ, давление, анкета).
Смена анализатора сдвигает отдельные лабораторные показатели, которые для диабета не главные. Это
и есть вывод «важен тип, а не размер сдвига».

**— Можно ли использовать эти модели в клинике?**
Нет. Это исследовательский бенчмарк о том, как правильно *проверять* модели, а не готовый
медицинский инструмент.

**— Что нового по сравнению с TabReD?**
(1) медицинские данные с несколькими периодами; (2) для каждого дрейфа найдена клиническая причина;
(3) сравнение на одном периоде показало, что метод сравнения в TabReD может давать артефакт.

**— Как воспроизвести?**
Ноутбук `CSCI447P034.ipynb` содержит весь код. При запуске он заново обучает выбранные модели и
сверяет результаты: 14 из 15 совпадают точно, у NHANES XGBoost разница 0,0004 (расчёт делался на
другом компьютере).

## 11. Словарь терминов

| Термин | Английский | Простыми словами |
|---|---|---|
| Признак | feature | один столбец таблицы (характеристика) |
| Целевая переменная | target / label | что предсказываем (да/нет) |
| Бинарная классификация | binary classification | предсказание одного из двух ответов |
| Обучающая выборка | training set | данные, на которых модель учится |
| Валидационная выборка | validation set | данные для выбора настроек и порога |
| Тестовая выборка | test set | «экзамен», используется один раз |
| Гиперпараметры | hyperparameters | настройки модели, которые выбираем мы (глубина деревьев и т. п.) |
| Переобучение | overfitting | модель «зазубрила» обучающие примеры и плохо работает на новых |
| Ранняя остановка | early stopping | прекращаем обучение, когда валидация перестаёт улучшаться |
| Эпоха | epoch | один проход нейросети по всем обучающим данным |
| Утечка данных | data leakage | признак, выдающий ответ, которого в реальности не было бы |
| Дрейф / сдвиг распределения | distribution shift / drift | данные меняются со временем |
| Сдвиг ковариат | covariate shift | меняются признаки (например, показания анализатора) |
| Сдвиг целевой переменной | label shift | меняется доля больных |
| Градиентный бустинг | gradient boosting (GBDT) | деревья, каждое исправляет ошибки предыдущих |
| Кросс-валидация | cross-validation | 5 раз учимся на 4/5 данных и проверяем на 1/5 |
| Бутстрэп | bootstrap | многократная перевыборка тестовых строк для интервала |
| Доверительный интервал | confidence interval | диапазон, где с 95% уверенностью лежит истинное значение |
| Порог | threshold | вероятность, выше которой ответ «да» |
| Матрица ошибок | confusion matrix | таблица TP / FP / FN / TN |
| Полнота | recall / sensitivity | доля найденных больных |
| Точность (положительных) | precision | доля настоящих больных среди «тревог» |
| Доменный классификатор | domain classifier | модель, отличающая старые данные от новых |
| Скользящее окно | sliding window | 3 года обучения → 1 валидации → 1 теста, сдвигается по времени |
| Бенчмарк | benchmark | стандартный набор задач для сравнения методов |
